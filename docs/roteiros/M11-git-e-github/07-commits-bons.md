# Roteiro de vídeo — Aula 11.7: Commits bons

**Módulo 11 — Git e GitHub** · Duração alvo: ~5 min
Apresentação em Libras · Apoio: legenda e transcrição em português

---

## Objetivo da aula
- Escrever boas mensagens de commit

## Termos técnicos a preparar antes
- **feat / fix / docs / refactor** — datilologia; os prefixos de commit.
- Dica-guia: completar a frase "este commit vai...".

## Visão geral de gravação
- **Ritmo geral:** médio.
- **Tom predominante:** de boa prática.
- **Enquadramento:** meio-corpo; ruim × bom na tela.

## Roteiro (frase a frase)

### 1. Abertura · ~30s
*Expressão: clara · Ritmo: lento*
- "Um bom commit é pequeno."
- "E tem uma mensagem clara, que diz o que mudou."

### 2. Padrão comum · ~70s
*Expressão: didática · Ritmo: lento · Corpo: liste os prefixos*
- `[MOSTRAR NA TELA: feat: nova funcionalidade · fix: correção · docs: documentação · refactor: reorganizar]`
- "feat: nova funcionalidade."
- "fix: correção de bug."
- "docs: documentação."
- "refactor: reorganizar sem mudar o comportamento."

### 3. Ruim × bom · ~55s
*Expressão: comparativa · Ritmo: lento · Corpo: vago × claro*
- `[MOSTRAR NA TELA: "mudanças", "aaa", "coisas" (ruim) × "feat: adiciona validação no login" (bom)]`
- "Mensagens como 'mudanças' ou 'aaa' não dizem nada."
- "'feat: adiciona validação no formulário de login' conta a história."
- "Dica: escreva completando a frase 'este commit vai...'."
- "Por exemplo: '...adicionar a tela de login'."

### 4. Fechamento · ~20s
*Expressão: conclusiva · Ritmo: lento*
- "Resumo: commits pequenos, mais mensagens claras, contam a história do projeto."
- "Na próxima aula: publicando o projeto."

**Soma estimada:** ~2m55s (alvo: ~5 min)

## Checklist de gravação
- [ ] Datilologia dos prefixos feat/fix/docs/refactor
- [ ] Tela de apoio: mensagens ruins × boas
- [ ] Dica da frase 'este commit vai...'
